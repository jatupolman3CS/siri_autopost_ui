# AutoPost UI (Angular)

Frontend ของ **AutoPost** สร้างตามดีไซน์ "AutoPost Dashboard" จาก Claude Design handoff ด้วย **Angular 22** (standalone, zoneless, signals) รองรับภาษาไทย/อังกฤษ และโหมดสว่าง/มืด

> หน้าเว็บเดิม (Vite + ไฟล์ dashboard ของส่วนขยาย) อยู่ที่ [`legacy/`](legacy/README.md) และยังรันได้เหมือนเดิม

## หน้าจอที่มี

| กลุ่ม | หน้า |
|---|---|
| สาธารณะ | หน้าแรก (landing + ราคา), เข้าสู่ระบบ, สมัครใช้ฟรี (แผน Free ใช้ได้ตลอด ไม่มีช่วงทดลอง) |
| เวิร์กสเปซ (3 ขั้น) | ภาพรวม (3 ขั้นเริ่มต้น), **ชุดโพสต์** (+ หน้าเขียนโพสต์), **ลิงก์กลุ่มและชุดลิงก์** (รหัสกลุ่ม, วางหลายลิงก์, CSV, ดึงจากบัญชี), **ตารางโพสต์** (รายวัน/จันทร์–ศุกร์/ศุกร์–อาทิตย์/เป็นรอบ/กระจายทั้งวัน/ครั้งเดียว), ปฏิทินโพสต์, คลังสื่อและข้อความ, รายงาน |
| ระบบโพสต์อัตโนมัติ | ทดลองโพสต์, ความปลอดภัยบัญชี (anti-ban + ตั้งค่าขั้นสูง + สำรอง/กู้คืน), การแจ้งเตือน (Telegram / LINE OA), ตอบกลับอัตโนมัติ, เมื่อออฟไลน์, รายงานข้อผิดพลาด (หน้าตั้งค่าชุดโพสต์ของส่วนขยายเดิมอยู่ที่ `/app/campaigns` เข้าจากหน้าตัวอย่างส่วนขยาย) |
| บัญชีผู้ใช้ | แผนและการชำระเงิน, ทีมและเวิร์กสเปซ |
| เจ้าของแพลตฟอร์ม (admin) | ภาพรวมแพลตฟอร์ม, ลูกค้า + รายละเอียดลูกค้า, การเงิน, แผนและโค้ดส่วนลด, งานที่กำลังรัน |
| สาธารณะ (ไม่ต้องล็อกอิน) | รายงานส่งลูกค้า `/report/<token>` (แผน Agency) |
| ตัวอย่าง | หน้าต่างส่วนขยาย (popup) |

**สถานะข้อมูล:** หน้าเวิร์กสเปซและระบบโพสต์อัตโนมัติใช้ข้อมูลจริงจาก `SIRIAUTOPOST.Api` (repo `siri_autopost_backend`):
สมัคร/เข้าสู่ระบบ (JWT), เวิร์กสเปซ, บัญชีโซเชียล, ตั้งเวลาโพสต์/แก้/ลบ, ปฏิทิน, รายงานข้อผิดพลาด (ลองใหม่/ข้าม/เชื่อมต่อใหม่), อัปโหลดสื่อและข้อความสำเร็จรูป, ตั้งค่า anti-ban และเมื่อออฟไลน์, จำลองส่วนขยายออฟไลน์, เปลี่ยนแผน และ **อุปกรณ์**: จับคู่ส่วนขยายด้วยรหัส (หน้าทีมและเวิร์กสเปซ > เพิ่มอุปกรณ์) แล้วส่วนขยายในเครื่องนั้นจะโพสต์ลงกลุ่ม Facebook ตามเวลาที่ตั้งไว้ และส่งผลกลับมาที่ปฏิทิน/รายงานข้อผิดพลาด

ตั้งแต่ Phase 4 ใช้ข้อมูลจริงเพิ่ม: **ทีม** (เชิญสมาชิกด้วยอีเมล, บทบาทผู้ชม/ผู้แก้ไข/ผู้ดูแล, นำออก/ออกจากทีม), **แผนและใบแจ้งหนี้** (ราคาและข้อจำกัดจากเซิร์ฟเวอร์, โค้ดส่วนลด, รายปีลด 20%) และ **หน้าเจ้าของแพลตฟอร์ม** ทั้งหมด (ลูกค้า, ระงับ/แบน/หยุดงาน, ข้อจำกัดรายลูกค้า, คืนเงิน, รายได้, แผนและโค้ดส่วนลด, งานที่กำลังรัน)

Phase 5: ภาพรวมแพลตฟอร์มใช้ **ตัวเลขจริง** (MRR เทียบ 30 วันก่อน, churn, ส่วนขยายที่ใช้งาน, อัตราสำเร็จ, latency ของ API, ฐานข้อมูล, คิว, อัตราข้อผิดพลาด), หน้าลูกค้ามี **ประวัติการดำเนินการ** และปุ่ม "ช่วยเหลือ" เปิดแดชบอร์ดของลูกค้า **แบบดูอย่างเดียว** 1 ชั่วโมง (มีแถบด้านบนให้กลับไปหน้าแอดมิน)

Phase 6: หน้า **ชุดโพสต์ (ส่วนขยาย)** = หน้าตั้งค่าของส่วนขยายบนเว็บ ครบทุกอย่าง: ชุดโพสต์ (เพิ่ม/ทำสำเนา/ลบ/เปิดปิด), กลุ่ม (ข้อความเฉพาะกลุ่ม/รหัส, โพสต์ได้ต่อวัน, เพิ่มหลายกลุ่มพร้อมกัน), เนื้อหาหลายแบบ + spintax + {{code}}, สื่อนำหน้า, รูป/วิดีโอ, ข้อความเพิ่มทุกโพสต์ + ตำแหน่ง, แท็กเพจ, ค้นหา/แทนที่, หน่วงเวลา/รอบ/ช่วงเวลา, พฤติกรรมสุ่ม, ตั้งค่ารวม + กันโดนบล็อก, Telegram (ดึง Chat ID, ส่งทดสอบ), ภาพรวมทุกชุด, ทดสอบโพสต์ 1 กลุ่ม, ดาวน์โหลด/อัปโหลดการตั้งค่า, ไฟล์ config ของโฟลเดอร์ส่วนขยาย, นำเข้า SIRI export และบันทึกการทำงาน ส่วนขยายที่จับคู่ไว้ส่งการตั้งค่าของตัวเองขึ้นมาเองตอนจับคู่ แล้วซิงก์ทุก 30 วินาที (แก้ที่ไหนก็ได้ แก้พร้อมกันใช้ของเว็บ) ปุ่มเริ่ม/หยุด/โพสต์ทันที/ทดสอบส่งไปทำที่เครื่องนั้น

Phase 7: **ส่วนขยายเป็นแค่ตัวโพสต์ + หน้าสถานะ** การตั้งค่า การจับคู่ และการควบคุมเครื่องอยู่ที่เว็บทั้งหมด: ทีมและเวิร์กสเปซ > เพิ่มอุปกรณ์ > **เชื่อมต่อ Chrome เครื่องนี้** (กดอนุญาตครั้งเดียวในหน้าที่ส่วนขยายเปิดขึ้น), เปลี่ยนชื่อเครื่อง, พักรับงาน/รับงานต่อ, ยกเลิกการผูก (ส่วนขยายกลับเป็นยังไม่ได้เชื่อมต่อเอง)

Phase 9 (ดีไซน์ BRD deliverables and approach): ขั้นตอนใหม่ **ชุดโพสต์ → ชุดลิงก์กลุ่ม → ตารางโพสต์** ใช้ข้อมูลจริงทั้งหมด (ตารางสร้างโพสต์ที่รอคิวล่วงหน้า 14 วันให้ส่วนขยายมารับ), ทดลองโพสต์จริง 1 โพสต์พร้อมบันทึกความคืบหน้าจริง, การแจ้งเตือน Telegram/LINE OA ที่เซิร์ฟเวอร์ส่งให้, รายงานต่อกลุ่ม/ต่อโพสต์ + ลิงก์รายงานลูกค้า, ตั้งค่า anti-ban ขั้นสูงที่เซิร์ฟเวอร์บังคับใช้, สำรอง/กู้คืนทั้งเวิร์กสเปซ และโหมดเมนูแบบง่าย ส่วนที่ระบบเก็บไว้แต่ยังไม่ทำงาน (กฎตอบกลับอัตโนมัติ, บั๊มโพสต์/ลบอัตโนมัติ, ลายน้ำ, แท็กเพจ, คำสั่งผ่านบอท) จะมีป้ายบอกในหน้า และยอดไลก์/คอมเมนต์ยังไม่มีข้อมูล

**การชำระเงินใช้ Stripe:** เลือกแผนเสียเงินแล้วหน้าเว็บพาไป Stripe Checkout (บัตรกรอกที่ Stripe ไม่ผ่านระบบเรา), บัตรและใบแจ้งหนี้จัดการที่ Stripe billing portal, แผนเปลี่ยนก็ต่อเมื่อ Stripe ยืนยัน (ตอนกลับจาก Checkout หรือ webhook), เปลี่ยนแผน/รอบบิลคิดส่วนต่างทันที, เลือก Free = ยกเลิกเมื่อสิ้นรอบ, แอดมินคืนเงินและลองเก็บเงินใหม่ได้จากหน้าการเงิน ถ้า API ไม่ได้ตั้ง `Stripe__SecretKey` หน้าเว็บจะบอกว่ายังไม่เปิดรับชำระออนไลน์ (ตั้งค่า Stripe ดู README ของ `siri_autopost_backend`) ระบบนี้ทดสอบกับ Stripe จำลองเท่านั้น ยังไม่เคยรันกับ Stripe จริง

ยังเป็น **ข้อมูลตัวอย่าง**: รายการกิจกรรมในหน้าต่างส่วนขยายตัวอย่าง และภาพตัวอย่างบนหน้าแรก
เวิร์กสเปซใหม่จะมีบัญชีโซเชียลและประวัติโพสต์ตัวอย่างให้ลองใช้ (ป้าย "ตัวอย่าง") โพสต์ของบัญชีตัวอย่างไม่ถูกส่งจริง ส่วนขยายโพสต์ได้เฉพาะบัญชี "Facebook · ชื่อเครื่อง" ที่ได้จากการจับคู่ และเฉพาะโพสต์ลงกลุ่ม

Phase 8 (ตรวจความสอดคล้องกับระบบจริง): ทุกปุ่มที่ API จะตอบ 403 ใช้ไม่ได้และบอกเหตุผล (บทบาทผู้ชม/ผู้แก้ไข/ผู้ดูแล และโหมดช่วยเหลือที่ดูได้อย่างเดียว, `PermissionsService`), ข้อจำกัดของแผน (ที่นั่ง อุปกรณ์ anti-ban ขั้นสูง) มาจากเวิร์กสเปซ/API ไม่ใช่แผนของผู้ใช้ที่ล็อกอิน, ตัวเลขการใช้งานนับเฉพาะบัญชีที่ต่อส่วนขยายและโพสต์ใน 24 ชั่วโมงที่ผ่านมา, หน้าจอแสดง "—" จนกว่าข้อมูลจะมาและโหลดซ้ำเมื่อเซิร์ฟเวอร์ล่ม, รายการบัญชี/อุปกรณ์ตามเหตุการณ์สดจากส่วนขยาย, หน้าแอดมินโหลดใหม่ทุกครั้งที่เข้าและหลังทุกการกระทำ (วันที่เรื่องเงินใช้ปฏิทินกรุงเทพฯ), โค้ดส่วนลดเปิด/ปิดได้และแสดงสถานะหมดอายุ, ข้อความของดีไซน์ที่ไม่ตรงกับระบบถูกแก้ใน `i18n.fixes.ts` (ไม่มีช่วงทดลอง 14 วัน, สาเหตุที่โพสต์ไม่ผ่านไม่ผูกกับ TikTok/LINE, เพดานต่อวันทำให้โพสต์ล้มเหลวไม่ได้เลื่อนไปวันถัดไป), ตัวเลือกที่ส่วนขยายยังไม่ทำ (สุ่มลำดับกลุ่ม หยุดอัตโนมัติ วอร์มอัพ แจ้งเตือนผ่าน LINE/อีเมล/เบราว์เซอร์) แสดงแต่ปิดไว้พร้อมป้าย "ยังไม่รองรับ" และหลังล็อกอินกลับไปหน้าที่เปิดค้างไว้

Phase 10 (ตรวจรอบสอง): **กู้คืนไฟล์สำรองต้องกดสองครั้ง** (ตรวจไฟล์ แล้วดูสรุปว่าไฟล์มีอะไรและจะแทนที่อะไรก่อนกดยืนยัน), หน้าต่างทุกบานเป็น dialog ที่เข้าถึงได้ (โฟกัสเข้าและคืนโฟกัส, Tab วนอยู่ในหน้าต่าง, Esc ปิด), รายงานลูกค้าสาธารณะแสดงเฉพาะแบรนด์ของสแนปช็อต (ไม่เปิดชื่อเวิร์กสเปซในรายงาน white-label, กลุ่มที่ไม่มีลิงก์แสดงเป็นข้อความ) และเปิดในแท็บใหม่แบบ noopener, ตัวช่วยร่างโพสต์เรียกว่า "แม่แบบ" ไม่ใช่ AI เพราะไม่มีโมเดลภาษา, หน้าที่ถูกล็อกด้วยแผนไม่กะพริบแถบล็อกก่อนโหลดเวิร์กสเปซเสร็จ, ปฏิทินวันที่ผ่านไปแล้วเพิ่มตารางไม่ได้, นำเข้า CSV ต้องเป็น UTF-8 ไม่เกิน 2 MB, ชั่วโมงที่แนะนำของตารางแยกตามเวิร์กสเปซ, ป้าย "บันทึกไว้เท่านั้น" บอกชัดว่ายังไม่มีส่วนใดนำค่านั้นไปใช้ และหน้าทดลองโพสต์บอกว่าเป็นโพสต์จริง ไม่ใช่การจำลอง

## เริ่มพัฒนา

ต้องใช้ Node.js **22.22.3+** หรือ **24.15+**

ต้องรัน API ก่อน (ดู README ของ `siri_autopost_backend`: `cd src/SIRIAUTOPOST.Api && dotnet run` ที่ http://localhost:5100) แล้ว:

```bash
npm install
npm start          # http://localhost:4200 (ส่ง /api ไปที่ http://localhost:5100)
npm test           # unit test (Vitest)
npx prettier --check .   # ตรวจรูปแบบทั้ง repo (.prettierignore ข้าม legacy/ และไฟล์ที่ไม่ได้จัดรูปแบบ)
npm run build      # -> dist/siri-autopost-ui/browser
npm run gen:api    # สร้าง type ของ API ใหม่จาก openapi.snapshot.json
```

รันทั้งระบบด้วย Docker (PostgreSQL + API + หน้าเว็บนี้ผ่าน nginx): ดู `docker-compose.saas.yml` ใน `siri_autopost_backend` (`Dockerfile` และ `nginx.conf` ของ repo นี้คือคอนเทนเนอร์ `web`)

บัญชีผู้ดูแลตอนพัฒนา: `admin@autopost.local` / `admin1234` หรือสมัครบัญชีใหม่ได้ที่ `/signup` (รหัสผ่าน 8-100 ตัวอักษร)

```text
src/styles/          # tokens (สี/ระยะ/เงา), CSS ของ design system, layout utilities
```
